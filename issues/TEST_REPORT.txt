CONFIRMED ISSUES
----------------
ID: TST-001
Severity: HIGH
Module: Grounded comparison jobs / Research-space deletion
Reproduction:
  cd backend && .venv/bin/python -m pytest \
    tests/unit/compare/test_grounded_compare.py::test_deleting_space_stops_its_running_job
Expected:
  Deleting a research space cancels or otherwise safely terminates every
  comparison job belonging to it. The task finishes and removes its task entry
  without attempting to persist to a deleted AnalysisJob row.
Actual:
  The task is cancelled while waiting on the model client, then its cleanup/
  state-update path attempts to update analysis_jobs after the row has been
  deleted. SQLAlchemy raises:
    StaleDataError: UPDATE statement on table 'analysis_jobs' expected to
    update 1 row(s); 0 were matched.
Evidence:
  backend/tests/unit/compare/test_grounded_compare.py, test beginning at line
  667; full-suite failure: 1 failed, 263 passed, 5 skipped.
Risk:
  A user deleting a space while a grounded comparison is running can leave an
  unhandled task exception and an inconsistent background-job lifecycle.
Recommended correction:
  Make cancellation/deletion ownership explicit and idempotent. Before any
  background-job terminal-state update, re-read or conditionally update the job
  row; treat a missing row caused by parent-space deletion as an expected
  cancellation outcome. Add regression coverage for cancellation at every
  awaited job phase and for repeated deletion/cancellation requests.
Resolution:
  update_job now confirms whether the job still exists after a stale database
  update. A stale update is ignored only when deletion removed the job row;
  all other stale updates still raise normally.
Verification:
  Focused deletion-race regression: passed.
  Complete backend suite: 264 passed, 5 skipped.
State: RESOLVED
